## Overview

This major release delivers four changes:

1. **OpenAPI spec update** — advance the pinned spec SHA to `c7d0fed479f9c477682619b8d44b65966e0adbf0`
   and regenerate all server models.
2. **v1/events removal** — delete the entire `/v1/events` stack (controller, service,
   storage, mapper, static lookup table, legacy encoder) and remove the corresponding
   routing rule and tests.
3. **CORS support** — frontend applications receive
   `Response body is not available to scripts (Reason: CORS Missing Allow Origin)`
   because the backend does not emit `Access-Control-Allow-Origin` headers. Browsers
   block cross-origin responses without these headers, making every API call fail in
   browser environments.
4. **Version bump** — advance the application version in `pyproject.toml` from `1.0.0`
   to `2.0.0` to reflect the breaking removal of the `/v1/events` API.

**Backward compatibility:** `/v1/events` is intentionally removed in this release.
All `/v2/*` endpoints must continue to work unchanged.

### STEP 4 — Add CORS middleware to `__main__.py` [parallel-safe with steps 2–3]

**File:** `src/main/__main__.py`

**Root cause:** The connexion/uvicorn ASGI stack does not inject CORS headers by default.
Browsers send a preflight `OPTIONS` request before any cross-origin `GET`/`POST`. Without
`Access-Control-Allow-Origin` in the response, the browser blocks the response body.

**Fix:** Add starlette's `CORSMiddleware` to the connexion application. `starlette` is
already a declared dependency (`Pipfile` / `requirements.txt`) — no new package is needed.

**Implementation:**

1. Read allowed origins from the `CORS_ALLOWED_ORIGINS` environment variable
   (comma-separated list, e.g. `https://app.example.com,http://localhost:3000`).
   Fall back to `["*"]` when the variable is absent or empty.

2. Register the middleware at `BEFORE_ROUTING` so that:
   - Preflight `OPTIONS` requests are answered before the router runs.
   - All API responses carry CORS headers regardless of routing outcome.

```python
from starlette.middleware.cors import CORSMiddleware

# inside main(), before app.add_api(...); os is already imported at the top of the file
_raw_origins = os.environ.get("CORS_ALLOWED_ORIGINS", "")
allowed_origins = [o.strip() for o in _raw_origins.split(",") if o.strip()] or ["*"]

app.add_middleware(
    CORSMiddleware,
    position=MiddlewarePosition.BEFORE_ROUTING,
    allow_origins=allowed_origins,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**Placement relative to existing middleware:**

connexion places each middleware according to its `position` parameter, not registration
order. `BEFORE_ROUTING` is outer in the stack than `BEFORE_VALIDATION`, so
`CORSMiddleware` will always wrap around `StripEmptyArrayParams` regardless of which
`add_middleware` call appears first in the source. The final middleware configuration
should read:

```python
app.add_middleware(StripEmptyArrayParams, position=MiddlewarePosition.BEFORE_VALIDATION)
app.add_middleware(
    CORSMiddleware,
    position=MiddlewarePosition.BEFORE_ROUTING,
    allow_origins=allowed_origins,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

**Acceptance criterion:**
- A cross-origin `OPTIONS /v2/events` request returns HTTP 200 with
  `Access-Control-Allow-Origin` present in the response headers.
- A cross-origin `GET /v2/events` request returns `Access-Control-Allow-Origin` in the
  response headers.
- All existing integration tests still pass.

### STEP 6 — Write CORS integration tests

**New file:** `src/test/python/test_events/test_cors.py`

Tests that CORS headers are emitted on real HTTP responses and that preflight `OPTIONS`
requests are handled correctly. All tests use the existing `BaseTestCase` client — no
real network calls.

```python
import unittest
from python.test_events import BaseTestCase


class TestCors(BaseTestCase):

    def test_get_request_has_allow_origin_header(self):
        """Regular GET responses must carry Access-Control-Allow-Origin."""
        response = self.client.open(
            "/v2/metadata/event-types",
            method="GET",
            headers={"Origin": "https://app.example.com"},
        )
        self.assert200(response)
        self.assertIn("Access-Control-Allow-Origin", response.headers)

    def test_options_preflight_returns_200(self):
        """Browser preflight (OPTIONS) must be answered before routing."""
        response = self.client.open(
            "/v2/events",
            method="OPTIONS",
            headers={
                "Origin": "https://app.example.com",
                "Access-Control-Request-Method": "GET",
                "Access-Control-Request-Headers": "Content-Type",
            },
        )
        self.assertIn(response.status_code, (200, 204))

    def test_options_preflight_has_allow_origin_header(self):
        """Preflight response must include Access-Control-Allow-Origin."""
        response = self.client.open(
            "/v2/events",
            method="OPTIONS",
            headers={
                "Origin": "https://app.example.com",
                "Access-Control-Request-Method": "GET",
            },
        )
        self.assertIn("Access-Control-Allow-Origin", response.headers)
```

> **Note:** `BaseTestCase` spins up the full connexion ASGI app, so `CORSMiddleware` is
> active during these tests — no mocking of the CORS layer is needed or appropriate.

**Acceptance criterion:**
- All three tests pass with `python3 -m pytest src/test/python/test_events/test_cors.py -v`.
- Full suite passes: `python3 -m pytest src/test/python/ -v`.
